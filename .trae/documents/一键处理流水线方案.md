# 视频帧「一键处理」流水线方案

## Context（为什么做）

当前「视频帧」页的处理链被拆成三个互相独立的入口：工具栏抽帧、`FrameCropModal` 批量裁切、`FrameMatteModal` 批量抠图。用户要完成「视频 → 成品帧」需要手动点三次，且每次都要重新确认参数；模型是否已加载只能去「抠图」页看，帧抠图弹窗里没有任何前置校验，首次执行必然在推理中途才发现要下载模型。

本次要新增「一键处理」：一次配置按 **抽帧 → 裁切 → 抠图** 顺序跑完，裁切与抠图可勾选启用（未勾选即跳过），结束后在弹窗内预览与导出；执行前确保模型已加载。

同时用户明确要求「整理代码，达到复用的最高」——目前抽帧/裁切/抠图的实现分别散落在 `VideoPage.vue`、`FrameCropModal.vue`、`FrameMatteModal.vue`，`loadImage` 等工具函数有两份拷贝，模型状态是 `MattePage.vue` 的组件内局部状态。因此本次一并把可复用逻辑下沉到 `core`、把模型状态提升为共享 store、把可复用 UI 拆成组件。

已确认的决策：按钮放在**视频帧页工具栏**；处理结果**写入现有 `workspace.video.frames`**（与手动流程共用一份数据）；抠图默认引擎 **BiRefNet**（本地权重、离线可用）；抠图方式**允许切回纯色算法**。

### 新增 core 模块（纯函数、无 UI）

### 新增共享 store

`src/store/model-status.ts`：把 `MattePage.vue` 中**局部**的模型状态全量上移，供「抠图」页与一键处理弹窗共用。
- `type ModelState = 'unknown' | 'loading' | 'ready' | 'error'`
- `type ModelEngine = 'imgly' | 'birefnet' | 'rmbg' | 'sam'`
- `modelStatus: reactive<Record<string, { state: ModelState; message?: string }>>`
- `matteModelKey(engine)`：按 `engine | 模型 id | 精度 | 设备 | 托管源 | publicPath` 拼 key（读取 `workspace.matte` 的 AI 偏好）→ 参数一变 key 就变，旧状态自动失效
- `modelStateLabel(state)`
- `ensureMatteModelLoaded(engine, onProgress?)`：`ready` 直接返回；`loading` 复用同一个 pending Promise（避免并发重复加载）；`error` 允许重试。内部调用现有 `preloadMattingModel`（`src/core/ai-matting.ts`）

`MattePage.vue` 改为导入该 store，删除自身的 `modelStates`/`selectedModelKey`/`modelStateLabel`/`preloadSelectedModel` 实现，只保留 UI 与把进度写入 `workspace.matte.aiStatus/aiProgress` 的回调。

## 二、一键处理弹窗与流水线编排

### 弹窗结构（`FramePipelineModal.vue`）

1. **步骤一 · 抽帧**（常驻，`ExtractSettingsFields`）
2. **步骤二 · 裁切**（勾选框 `cropEnabled`）— 勾选后展开 `FrameCropEditor`
3. **步骤三 · 抠图**（勾选框 `matteEnabled`，默认开启）— 勾选后展开 `MatteSettingsFields` + 模型状态行（`modelStateLabel`）与「预加载模型」按钮
4. **执行区**：`TaskProgress`（当前阶段、整体百分比、取消）
5. **结果区**：处理完成后展开 `FramePreviewPlayer` + `FrameExportActions`

底部主按钮：未加载模型时显示「加载模型并开始处理」，已加载/无需模型时显示「开始一键处理」；运行中变为「取消」。

### 编排（`src/core/frame-pipeline.ts`）

```ts
export type PipelineStage = 'extract' | 'crop' | 'matte'
export interface PipelineInput {
  extract: ExtractOptions           // 复用 workspace.video 的抽帧参数
  crop: ImageCropRect | null        // null = 跳过裁切
  matte: FrameMatteSettings | null  // null = 跳过抠图
}
export interface CancelToken { cancelled: boolean }

/**
 * 按 抽帧 → 裁切 → 抠图 顺序执行，每步完成即写入 workspace.video.frames。
 * 未启用的步骤权重并入前一步，保证整体百分比单调递增；任一步失败即返回该阶段并保留中间结果。
 */
export async function runFramePipeline(
  video: HTMLVideoElement,
  input: PipelineInput,
  onProgress: (stage: PipelineStage, done: number, total: number, text: string, percent: number) => void,
  token: CancelToken,
): Promise<{ stage: PipelineStage; error?: unknown }>
```

- 单实例锁（模块级 `let running = false`）：运行期间按钮禁用，避免重复执行。
- 重跑前先清空 `matteUrl`/`cropUrl`，始终从 `frame.url` 出发执行，避免误差叠加。
- 每帧循环头检查 `token.cancelled`，循环尾 `await nextTick()` 让出主线程，保证进度与取消按钮可响应。
- 抠图步骤当前帧为「样板帧」时可直接复用弹窗里已生成的预览结果（沿用 `FrameMatteModal.batchApply` 的既有优化）。

## 三、模型前置校验

- `matteEnabled && workspace.video.matte.mode !== 'solid'` 时 `needsModel = true`，用 `matteModelKey(engine)` 查 `modelStatus`。
- `ready`：主按钮直接可点；`loading`：禁用并展示进度；`error`：显示 `describeMattingError` 的提示与「重试」。
- 执行前调用 `ensureMatteModelLoaded(engine, onProgress)`——已加载立即返回，未加载则先加载再进入抽帧，满足「先确保加载了才能执行一键处理」。
- 与「抠图」页共享同一 key 与状态：在任一页加载完，另一页立刻显示「已加载」。

## 四、数据与持久化

`src/store/workspace.ts`：

- `VideoState` 新增 `pipeline: { cropEnabled: boolean; matteEnabled: boolean; crop: ImageCropRect | null }`，默认 `{ cropEnabled: false, matteEnabled: true, crop: null }`（裁切需框选，默认关闭；抠图按需求默认开启）。
- `workspace.video.matte.mode` 默认值由 `'solid'` 改为 `'birefnet'`，落实「抠图默认使用模型抠图」；纯色仍可在两个弹窗中切换。
- `persistMediaSettings()` 追加持久化 `pipeline` 步骤开关与裁切区域（沿用 `atlas-slice:media-settings` 键）。
- 保持既有约定不变：`frameBaseUrl = matteUrl ?? url`（裁切输入图）、`frameImageUrl = cropUrl ?? matteUrl ?? url`（展示/导出优先级）。

## 六、验证方式

- **类型与构建**：`node_modules/.bin/vue-tsc -b --force`、`npx vite build` 均通过。
- **端到端（浏览器，沿用 `public/assets/testImages/生成2D卡通日系手绘Q版角色战斗视频.mp4`，720×720）**：
  1. 导入视频 → 打开「一键处理」：只勾选抠图（BiRefNet）→ 首次应显示模型加载进度，「开始」按钮在加载完成前不可用 → 跑完检查帧列表每帧带 `matted` 标识。
  2. 勾选裁切 + 抠图：框选区域 → 右侧预览即时变化 → 跑完检查 `frame.crop`/`cropUrl` 存在且帧列表显示裁切后的抠图结果。
  3. 两个都不勾：应只执行抽帧，帧为原始画面（无 `cropUrl`/`matteUrl`）。
  4. 运行中点「取消」：应立即停止并保留已完成帧。
  5. 结果区：动画预览可播放，导出 ZIP 与「下载当前帧」产出的 PNG 尺寸等于框选尺寸（或抠图后的原帧尺寸）。
- **手动流程回归**：帧列表「批量裁切」「移除背景」两个弹窗功能与改造前一致；「抠图」页模型状态显示与预加载仍正常（共享同一 store）。

## 七、风险与注意事项

- **内存**：每帧同时可能保留 `url`/`matteUrl`/`cropUrl` 三份 PNG dataURL，帧数多时占用显著；保持逐帧串行 + `await nextTick()`，并在预计帧数过大时给出提示。
- **AI OOM**：BiRefNet 在 CPU 下占用高，保持 `AI_MAX_SIDE_LIMIT = 1024`、FP16 默认，错误统一走 `describeMattingError` 引导切 ISNet 或 GPU。
- **裁切预览基准图**：弹窗打开时可能尚无帧，裁切步骤以 `frames[0]` 为样板；若无帧则用当前抽帧参数在 `start` 时刻探测抽一帧到临时 canvas 作为预览源（不写入 `frames`），并提示「预览基于首帧，实际按同一区域应用到全部帧」。
- **重复应用**：重复执行前清空派生字段，避免在已裁切/已抠图的画面上二次处理。
