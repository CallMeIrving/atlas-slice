# 工程检查与性能优化方案（P0 范围）

## Context

`atlas-slice` 是 Vue 3 + TS + Vite 6 的图集/精灵图工具。只读审计后确认了 4 处**直接影响交互流畅度**的运行时热点：渲染期同步 PNG 编码、画布重绘无节流、拖拽中反复重建数组、列表选中判断 O(N²)。

本次**只做这 4 处 P0 修复**，缩小改动面与回归风险；P1（控制点命中、棋盘格缓存、页面懒加载/代码分割、连通域提速）留待后续。不改数据模型、不动依赖版本、不动抽帧编码方式（已与用户确认）。

## P0-1 缩略图每次渲染都同步 PNG 编码

**问题**：[FrameList.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/FrameList.vue#L18-L26) 的 `thumb(frameId)` 与 [PreviewPlayer.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/PreviewPlayer.vue#L124-L132) 的 `thumbOf(id)` 都在**渲染期**直接 `getCropCanvas(frame).toDataURL()`。任何响应式变化（选中/勾选/帧数组变更）都会触发全帧重编码；且两者内部各自 `find()` 一次，叠加出 O(N²)。

**改动 1 — [atlas.ts](file:///Users/oubuwen/D/testPro/atlas-slice/src/store/atlas.ts)**

紧邻现有 `const cropCache = new Map<string, HTMLCanvasElement>()`（L122）新增缩略图缓存：

```ts
/** 帧缩略图缓存：与 cropCache 同生命周期，仅在 clearCropCache() 中统一失效 */
const cropThumbCache = new Map<string, string>()
```

在 `getCropCanvas`（L125-152）之后新增导出函数（带函数级注释）：

```ts
/** 获取帧的小尺寸缩略图 dataURL：长边压缩到 ≤48px 后编码，结果按帧 id 缓存 */
export function getCropThumb(frame: AtlasFrame): string
```

实现要点：
1. 若 `frame.matteUrl` 存在，直接返回它（与既有「存在 matteUrl 时优先使用」的约定保持一致）。
2. 命中 `cropThumbCache` 直接返回。
3. 取 `getCropCanvas(frame)`，按 `MIN_THUMB_EDGE = 48` 等比缩放绘制到小 canvas（`imageSmoothingEnabled = true`，缩略图允许插值），再 `toDataURL()`。
4. 写入缓存并返回；`try/catch` 失败时返回 `''`（保持调用方原语义）。

**改动 2** — `clearCropCache()`（L154-156）内追加 `cropThumbCache.clear()`。该函数已被 `loadImage` / `clearFrames` / `autoDetectFrames` / `addManualFrame` / `deleteFrame` / `normalizeSelectedFrames` / `nudgeSelectedFrame` / `setFrameRect` 全部调用，因此**无需逐个改动这些调用点**即可保证失效正确。

**改动 3 — [FrameList.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/FrameList.vue)**

- `thumb(frameId: string)` → `thumb(frame: AtlasFrame)`：去掉内部 `find()`，函数体只剩 `getCropThumb(frame)` 加 try/catch。
- 模板 L77 `:src="thumb(frame.id)"` → `:src="thumb(frame)"`（循环变量已是帧对象）。
- `import` 中 `getCropCanvas` 换为 `getCropThumb`；补 `import type { AtlasFrame } from '@/types/atlas'`。

**改动 4 — [PreviewPlayer.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/PreviewPlayer.vue)**

- `thumbOf(id: string)` → `thumbOf(frame: AtlasFrame)`，函数体改为 `getCropThumb(frame)`。
- 模板 L189 `:src="thumbOf(f.id)"` → `:src="thumbOf(f)"`（`v-for` 已有 `f`）。
- `import` 中 `getCropCanvas` 换为 `getCropThumb`；补 `import type { AtlasFrame } from '@/types/atlas'`。
- 注意：`draw()` 中仍需要 `getCropCanvas(frame)`（预览主体要原尺寸），**保留该 import**。

> 两处重复的缩略图逻辑合并为 store 内单一实现，符合「不生成重复代码」。

## P0-2 CanvasStage 重绘无节流

**问题**：[CanvasStage.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/CanvasStage.vue#L223) 的 `watchEffect(render)` 让平移/缩放/resize 的每个 mousemove 都同步全量重绘（`render` L140-221：整图 `drawImage` + 遍历全部帧 `strokeRect` + 控制点 + 遮罩）。

**改动**（[CanvasStage.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/CanvasStage.vue)）

在 `render()` 定义之后、`watchEffect` 之前新增：

```ts
/** 重绘帧句柄：同一帧内的多次数据变更合并为一次绘制 */
let renderRaf = 0
/** 申请一次重绘（rAF 合并）：已排队则直接返回 */
function scheduleRender(): void {
  if (renderRaf) return
  renderRaf = requestAnimationFrame(() => {
    renderRaf = 0
    render()
  })
}
```

- L223 `watchEffect(render)` → `watchEffect(scheduleRender)`。
- `onMounted`（L506-512）：在 `window.addEventListener('resize', zoomFit)` 前后追加 `scheduleRender()`，确保挂载后首帧一定绘制（原先依赖 `watchEffect` 的即时执行）。
- `onBeforeUnmount`（L514-519）：追加 `if (renderRaf) cancelAnimationFrame(renderRaf)`。

**约束**：
- `zoomFit()`（L226-235）与 `fitView()` 仍同步写入 store，不改为 rAF；`onMounted` 里保留的 `requestAnimationFrame(zoomFit)` 不变，保证首帧适配结果正确。
- `render()` 内部实现不改，只改触发时机。

## P0-3 磁吸候选数组每次 mousemove 重建

**问题**：`magnetCandidates(src, excludeId)`（L272-281）遍历全部帧构建 `xs`/`ys`，被 `applyResize`（L90-116）与 `updateDraft`（L291-302）在**每次 mousemove** 调用。

**改动**（[CanvasStage.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/CanvasStage.vue)）

1. 在 `magnetCandidates` 之后新增模块内缓存与访问器：

```ts
/** 拖拽期间的磁吸候选缓存：拖拽开始时计算一次，结束时清空 */
let magnetCache: { xs: number[]; ys: number[] } | null = null

/** 读取（必要时构建）磁吸候选；excludeId 变化时重新构建 */
function getMagnet(excludeId?: string): { xs: number[]; ys: number[] }
```

`getMagnet` 内部：`store.source` 为空时返回空候选；命中 `magnetCache` 直接返回；否则调 `magnetCandidates(src, excludeId)` 并写入缓存。为避免误用陈旧缓存，缓存中一并记录 `excludeId`（用 `cached.excludeId` 做比对），不一致则重建。

2. `onDown`（L313）中两处进入拖拽的分支各预热一次缓存：
   - 命中控制点、设置 `resizing.value` 之后 → `magnetCache = magnetCandidates(src, sel.id)`（即该帧自身被排除）。
   - 进入框选分支、设置 `drawing.value = true` 之后 → `magnetCache = magnetCandidates(src)`（框选无排除项）。
3. `onUp`（L376）与 `onLeave`（L370）中置 `magnetCache = null`（`onLeave` 覆盖拖拽中途移出画布的情况）。
4. `applyResize` 内 `const { xs, ys } = magnetCandidates(src, resizing.value?.id)` → `getMagnet(resizing.value?.id)`；`updateDraft` 内 `const { xs, ys } = magnetCandidates(src)` → `getMagnet()`。保留 `magnetCandidates` 原函数不删。

## P0-4 FrameList 选中判断 O(N²)

**问题**：[FrameList.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/FrameList.vue#L72) 模板中 `:checked="store.selectedIds.includes(frame.id)"` 每行做一次线性查找。

**改动**（[FrameList.vue](file:///Users/oubuwen/D/testPro/atlas-slice/src/components/FrameList.vue)）

`<script setup>` 中新增：

```ts
/** 选中 id 集合：把列表内的 O(N²) 包含判断降为 O(1) 查表 */
const selectedSet = computed(() => new Set(store.selectedIds))
```

模板中：`:checked="selectedSet.has(frame.id)"`。

进一步去重：现有模板 L42-45 的「全选/取消全选」按钮与 L44/L46 的文案判断共 4 处 `store.selectedIds.length === store.frames.length`，抽为：

```ts
/** 是否已全选（用于按钮文案与切换逻辑） */
const allSelected = computed(() => store.frames.length > 0 && store.selectedIds.length === store.frames.length)
```

模板改用 `allSelected`。这样 4 处重复表达式收敛为 1 处，且不再逐行计算。

## 验证方式

1. `npm run build`：必须通过 `vue-tsc` 类型检查并构建成功（这是本次唯一可自动化的门槛，用于确认 `AtlasFrame` 类型导入、缓存函数签名、模板参数变更无类型错误）。
2. `npm run dev`（后台已有 dev 任务占用端口，**不要重复启动**）：手动回归以下路径，要求与改动前**行为完全一致**：
   - 图集页：导入图集 → 自动识别 → 帧列表缩略图正常显示（含勾选后不闪烁卡顿）→ 选中帧 → 全选/取消全选按钮文案与行为正确 → 删除帧后列表与缩略图同步更新。
   - 画布：滚轮缩放、左键/空格拖拽平移、拖住控制点缩放边框（确认磁吸仍然生效且吸附到相邻帧边缘）、框选新增帧（确认磁吸生效）、方向键微调、`f` 自动适配、切「查看/框选」模式 —— 拖拽时不再每个 mousemove 全量重绘。
   - 动画预览：展开/收起、播放/暂停、上一帧/下一帧、帧序拖拽、自然排序，缩略条正常。
   - 换图 / 清空帧后重新识别：确认缩略图缓存已失效，新帧显示新缩略图（不是旧图），无残留。
3. 回归重点（缓存失效）：**同一帧改动矩形后（拖拽控制点 / 方向键微调 / Auto-fit），缩略图必须立即变新** —— 这是 `clearCropCache()` 联动 `cropThumbCache.clear()` 的核心验收点。
